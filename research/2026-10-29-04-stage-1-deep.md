# agentic-weave Stage 1: Agent Compatibility and Distribution

> Translated from the original Indonesian on 2026-11-01. Skill and package names are as they were when the research was written (`antiai-*` skills, the `anti-ai-skills` package, `bin/anti-ai.mjs`); they are now `weave-*`, `agentic-weave`, and `bin/agentic-weave.mjs`.
>

Those findings were applied in the skills that now live in the [deflow](https://github.com/cendysaputra/deflow) repository (`deflow`, `deflow-convert`, `deflow-ref`), whose references carry their sources and verification dates. The original Indonesian text of all sections is in git history at commit `dbda9c9`. This file keeps section A, which the installer in this repository still relies on.

Source: Research mode report, 29 October 2026. It replaced the overlapping parts of the earlier web search report.

Main conclusion: the SKILL.md format now works across agents. Grok Build, OpenCode, Amp, Cline, Kiro, and Windsurf/Devin Desktop have documented official skill paths, and several of them also read `.claude/skills` or `~/.agents/skills`. So the priority is not adding more installer paths. The priorities are (1) trimming skill descriptions and bodies to fit the specification limits and the catalog budget, (2) adding `AGENTS.md` and a Claude Code plugin installable from the same repository, then (3) building the flow and conversion skills with explicit artifacts and gates.

## TL;DR

- **Distribution:** keep `skills/<name>/SKILL.md` as the single source. Add `.claude-plugin/marketplace.json` (Claude Code supports `npm` plugin sources, so the npm package can be used directly) and `AGENTS.md`. Extend the installer to `~/.grok/skills`, `~/.config/opencode/skills`, `~/.cline/skills`, `~/.kiro/skills`, `~/.codeium/windsurf/skills`, and `~/.config/agents/skills` (Amp).
- **Skill quality:** arXiv 2607.01456 found 26 kinds of skill smell, an average of 10.5 smells per file, and only 1 clean file out of 238. arXiv 2608.11888 recorded 307 skill-induced failures. So every skill needs a validator, evals, and a body under 500 lines or 5,000 tokens, not just longer rules.

## 2. A. Cross-Agent Compatibility and Distribution

### A1. The agentskills.io specification

**FACT:**

| Field | Required | Limit |
|---|---|---|
| `name` | Yes | Max 64 characters, lowercase letters, digits, hyphens; may not start or end with a hyphen; must match the folder name |
| `description` | Yes | Max 1024 characters, not empty, says what the skill does and when to use it |
| `license` | No | License name or a pointer to a license file |
| `compatibility` | No | Max 500 characters, environment requirements |
| `metadata` | No | Free key-value map |
| `allowed-tools` | No | Space-separated string, experimental |

- Progressive disclosure has three levels: the catalog (name + description) loads when a session starts, the SKILL.md body loads when the skill activates (recommended under 5,000 tokens), and reference files load when needed. The agentskills.io integration guide puts the catalog at about 50 to 100 tokens per skill.
- File references use paths relative to the skill root, ideally only one level below SKILL.md.
- Validation is done with `skills-ref validate ./my-skill`.

**FACT:** According to the official Codex documentation, the skill list uses at most 2% of the model's context window, or 8,000 characters when the context window size is unknown, and Codex shortens descriptions first when many skills are installed. The limit can be changed with `skills.max_context_tokens`, up to 10,000 tokens.

**RECOMMENDATION:**

- The `antiai-ui` description was 903 characters at the time. That is under 1024, but 12 skills of that length would total about 10,800 characters and exceed Codex's 8,000-character budget. Target descriptions under 350 characters per skill. Pattern: "Do X. Use when Y, Z. Do not use for W."
- Put agent-specific fields (for example `metadata.hermes`, `paths`, `disable-model-invocation`) only under `metadata` or in fields that are safely ignored. Grok, for example, states that extra keys are ignored.
- Add `skills-ref validate` to CI.

Primary sources: https://agentskills.io/specification , https://agentskills.io/integrate-skills , https://github.com/agentskills/agentskills/blob/main/docs/specification.mdx

### A1b. Research on skill effectiveness

| Study | Key finding (FACT) | Implication for agentic-weave |
|---|---|---|
| arXiv 2607.01456 "From Anatomy to Smells" | 26 skill smells from a multivocal review of 29 sources; 11 smells appear in more than 50% of files; an average of 10.5 smells per file; only 1 of 238 files is smell-free; smells rarely disappear as skills evolve | Build `scripts/lint-skills.mjs` from the start; smells that get in are hard to remove later |
| arXiv 2608.11888 "Agent Skills Can Be Harmful" | 307 skill-induced failures (125 functional, 182 efficiency regressions); functional failures are often triggered by relevant skills; "Excessive Verification" accounts for 36.8% of efficiency regressions | The Delivery Gate must not make the agent repeat tests without limit; set an iteration cap (for example at most 2 rounds of compare-build) |
| arXiv 2610.08875 "Downstream Utility" | Measured on 87 SkillsBench tasks and 232 skills, with 3 LLMs and 3 harnesses; utility is the pass-rate difference against the no-skill condition | Stage 3 evals must compare results with and without the skill, not only check that the skill triggered |

Primary sources: https://arxiv.org/abs/2607.01456 , https://arxiv.org/html/2607.01456v1 , https://arxiv.org/html/2608.11888v1 , https://arxiv.org/html/2610.08875

**RECOMMENDATION, installer targets (in priority order):**

1. `~/.agents/skills` (Codex, Cursor, Copilot, OpenCode, Amp, Grok).
2. `~/.claude/skills` (Claude Code, OpenCode, Amp, and Grok through its Claude compatibility).
3. New targets not covered by the two paths above: `~/.gemini/antigravity-cli/skills`, `~/.gemini/config/skills`, `~/.hermes/skills`, `~/.cline/skills`, `~/.kiro/skills`, `~/.codeium/windsurf/skills`.

### A3. AGENTS.md

**FACT:**

- For nested files, the agents.md rule applies: the AGENTS.md closest to the edited file takes precedence, and an explicit user prompt overrides everything. The agents.md site says OpenAI's main repository has 88 AGENTS.md files and the format is used by more than 60,000 open source projects.
- In Claude Code (v2.1.277+), the default setting `claude-md-or-agents-md` reads AGENTS.md only when there is no CLAUDE.md, `.claude/CLAUDE.md`, or CLAUDE.local.md in the working directory and above. The other options are `claude-md-and-agents-md`, `claude-md`, and `managed-only`. A CLAUDE.md containing `@AGENTS.md` does not make AGENTS.md load twice.
- Grok Build reads the AGENTS.md family from the cwd up to the repository root. Amp uses AGENTS.md and falls back to CLAUDE.md when AGENTS.md is missing.
- Junie uses AGENTS.md as its default guidelines. When an old `.junie/guidelines.md` exists, the AGENTS.md content comes first.

**RECOMMENDATION, contents of this repository's AGENTS.md (target under 120 lines):**

1. Commands: `npm test`, `node bin/anti-ai.mjs --dry-run`, `skills-ref validate skills/*`.
2. Repository map: `skills/`, `bin/`, `scripts/`, `.claude-plugin/`, `research/`.
3. Skill-writing rules: Tell/Why/Fix + Rule entries, stable rule IDs, no em dashes, descriptions under 350 characters.
4. Pointers to skills: "For UI work read `skills/antiai-ui/SKILL.md`; for the end-to-end flow start from `skills/antiai-flow/SKILL.md`." Written as relative paths, not import syntax.
5. CLAUDE.md is a single `@AGENTS.md` line plus Claude-specific notes.

**RECOMMENDATION, an installer-managed marker block** (for AGENTS.md in client projects):

```md
<!-- agentic-weave:start v0.5.0 (managed by anti-ai-skills, do not edit by hand) -->
## agentic-weave
- Before handing over text, UI, a commit, or a PR: run the Delivery Gate in the antiai-core skill.
- Web project flow: follow the antiai-flow skill, artifacts in .antiai/.
<!-- agentic-weave:end -->
```

The installer only replaces the content between the markers and stores the version in the opening marker. This is a **RECOMMENDATION**, not an official standard.

Primary sources: https://agents.md/ , https://code.claude.com/docs/en/memory , https://docs.x.ai/build/features/skills-plugins-marketplaces , https://ampcode.com/manual/switch-from , https://youtrack.jetbrains.com/projects/JUNIE/issues/JUNIE-618/Support-AGENTS.md

### A4. Distribution

**FACT, Claude Code marketplaces:**

- The file lives at `.claude-plugin/marketplace.json`. Required top-level fields are `name`, `owner` (with `owner.name` required), and `plugins`. Optional fields: `$schema`, `description`, `version`, `metadata.pluginRoot`, `forceRemoveDeletedPlugins`, `allowCrossMarketplaceDependenciesOn`, and `renames`.
- Each plugin entry requires `name` and `source`. Optional fields: `description`, `version` (when `plugin.json` also sets `version`, `plugin.json` wins), `category`, `tags`, `strict` (default `true`), `dependencies`, `defaultEnabled`, and `displayName`.
- Plugin source types: relative path (starting with `./`), `github`, `url`, `git-subdir`, `npm` (`package`, `version`, `registry`; fetched without running install scripts), `archive`, and `command`.
- The names `agent-skills`, `anthropic-agent-skills`, `npm`, `github`, and names starting with `claudeai-` are reserved.
- Unknown keys are silently ignored, and `claude plugin validate` reports them as warnings.

**FACT:** Grok plugins bundle skills, agents, hooks, MCP, and LSP. Grok also reads Claude Code marketplaces and plugins automatically.

**RECOMMENDATION, structure:**

```json
{
  "name": "imajiner-agentic-weave",
  "owner": { "name": "Cendi Saputra", "url": "https://github.com/cendysaputra" },
  "description": "Anti-AI-slop skills for UI, Indonesian copy, commits, PRs, and the web agency flow",
  "plugins": [
    { "name": "agentic-weave", "source": "./", "description": "12+ agentic-weave skills", "category": "quality" }
  ]
}
```

Then `.claude-plugin/plugin.json` holds `{ "name": "anti-ai", "version": "0.5.0", "description": "...", "license": "MIT" }`. The versions in `plugin.json`, `package.json`, and the AGENTS.md marker are kept in sync by one script, `scripts/bump-version.mjs`. The marketplace name `imajiner-agentic-weave` is safer than `anti-ai-skills`. (The repository later used `agentic-weave` for both.)

**UNVERIFIED:** the details of the `npx skills add` and skills.sh CLI (the `-a` and `-g` flags, the lockfile). Secondary sources only show the pattern `npx skills add owner/repo --skill name` and `--agent windsurf`.

Primary sources: https://code.claude.com/docs/en/plugins/marketplace-reference , https://code.claude.com/docs/en/plugin-marketplaces , https://docs.x.ai/build/features/skills-plugins-marketplaces

### A5. Multi-file skills that depend on each other

**FACT:** The specification has no mechanism for dependencies between skills. File references are only relative to each skill's own root and recommended one level deep. The Claude marketplace has `dependencies` between plugins, not between skills.

**RECOMMENDATION:**

1. Each sub-skill (for example `antiai-ui`) carries a 10 to 15 line summary of the core rules from `antiai-core`, then writes "Full rules: read the antiai-core skill" as a text instruction, not a `../` path. Paths that leave the skill root break when skills are copied one at a time.
2. The installer always installs `antiai-core` together with any other skill (a hard dependency in `bin/anti-ai.mjs`).
3. For the Claude plugin, one plugin holds every skill, so dependencies always load.
4. Stable rule IDs (R-XX) are the contract: sub-skills cite IDs and do not copy long text.
